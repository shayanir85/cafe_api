# Frontend Code Review: Fixes Only (No Backend Changes)

## Context

Frontend-only review of the Cafe Order Management System. Covers both the Vue frontend (`cafe-api(Vue)/`) and the vanilla JS frontend (`FE/`), plus root-level repo hygiene. Backend (BK/) is explicitly excluded from this plan.

---

## Phase 1: Security & Correctness Fixes

### 1.1 XSS vulnerabilities in FE/ (vanilla JS) — multiple unescaped innerHTML injections
- `FE/SRC/Js/adminsManagement.js:112` — `err.message` injected into innerHTML
- `FE/SRC/Js/adminsManagement.js:235` — `displayName` in `data-name` attribute without escaping
- `FE/SRC/Js/adminsManagement.js:209,252` — `displayName` in innerHTML without escaping
- `FE/SRC/Js/menuManagement.js:529,532` — category names in onclick handlers; `escapeHtml()` doesn't escape single quotes, so `it's` breaks the JS string
- `FE/SRC/Js/ordersManagement.js:78` — `item.name` rendered without escaping
- `FE/SRC/Js/addToMenu.js:35` — `cat.name` in select option innerHTML
- `FE/SRC/Js/index.js:158` — `cat.name` in filter pill innerHTML
- **Fix:** Extend `escapeHtml()` to also escape single quotes (`'` → `&#39;`), then apply it to ALL user/API-supplied data before DOM insertion at each location listed above

### 1.2 Corrupted localStorage/sessionStorage crashes Vue app on load
- `cafe-api(Vue)/src/stores/auth.js:6-7` — `JSON.parse(sessionStorage.getItem(...))` without try/catch
- `cafe-api(Vue)/src/stores/cart.js:5` — `JSON.parse(localStorage.getItem(...))` without try/catch
- **Fix:** Wrap in try/catch with fallback to defaults:
```js
try { JSON.parse(val) } catch { fallback }
```

### 1.3 `fetchUser()` defined but never called — expired tokens appear logged in
- `cafe-api(Vue)/src/stores/auth.js:53-66` — validates stored token but never invoked
- **Fix:** Call `fetchUser()` in the router `beforeEach` guard or in `App.vue` `onMounted`, and handle failure by calling `clearAuth()`

### 1.4 Broken 401 redirect paths in FE/
- `FE/SRC/Js/api.js:34,463` — redirects to `/FE/Html/login.html` which doesn't exist
- **Fix:** Change to the correct relative path (e.g., `login.html` or the appropriate path based on where the page is served from)

### 1.5 401 interceptor public-route check is fragile in Vue
- `cafe-api(Vue)/src/services/api.js:26-27` — `window.location.pathname.endsWith(r)` matches any path ending in `/`, `/login`, or `/checkout`
- **Fix:** Use `startsWith` or exact match instead of `endsWith`

### 1.6 Hardcoded external domain in image fallback
- `cafe-api(Vue)/src/views/MenuPage.vue:192` — hardcoded `https://api.shayaniranpor.ir/images/menu-items/default.jpg`
- `FE/SRC/Js/index.js:195` — same hardcoded URL
- **Fix:** Use the existing `getImageUrl()` helper (Vue) or define the default image path as a constant (FE)

## Phase 3: DRY & Code Quality

### 3.1 Extract shared `escapeHtml()` utility in FE/
- Duplicated identically in 3 files: `FE/SRC/Js/index.js:20-28`, `FE/SRC/Js/checkout.js:154-162`, `FE/SRC/Js/menuManagement.js:56-64`
- **Fix:** Add to `FE/SRC/Js/api.js` and import in all consumers

### 3.2 Extract shared `showToast()` utility in FE/
- Duplicated 5x with slightly different implementations in: `checkout.js`, `ordersManagement.js`, `menuManagement.js`, `addToMenu.js`, `adminsManagement.js`
- **Fix:** Create a shared function in `api.js` or a new `utils.js`, unify the API (message, type, duration)

### 3.3 Extract shared cart logic in FE/
- `index.js:264-280` and `checkout.js:11-25` independently manage localStorage cart
- **Fix:** Extract `loadCart()`, `saveCart()`, `updateCartBadge()` to `api.js` or shared module

### 3.4 Extract `useToast()` composable in Vue
- Every Vue view (OrdersPage, MenuManagementPage, AddMenuPage, AdminsPage, CheckoutPage) implements its own toast with different APIs
- **Fix:** Create `cafe-api(Vue)/src/composables/useToast.js` and use in all views

### 3.5 Remove redundant inline auth checks in Vue
- Router already has `requiresAuth`/`requiresAdmin` guards, yet `OrdersPage:13-15`, `MenuManagementPage:16-18`, `AddMenuPage:11-13`, `AdminsPage:11-13` repeat the check
- **Fix:** Remove redundant inline checks; rely on router guards

### 3.6 Fix `checkout.js` module pattern
- `FE/SRC/checkout.html:125` — loads `checkout.js` without `type="module"`
- `checkout.js` uses dynamic `import()` and `window.` globals inconsistently
- **Fix:** Add `type="module"` to the script tag, remove `window.` assignments

## Verification Plan

After implementing fixes, verify with:

1. **Vue frontend:** `cd "cafe-api(Vue)" && npm run dev` — pages load without console errors, login works, cart persists, expired tokens redirect to login
2. **FE frontend:** Open `FE/SRC/index.html` in browser — menu loads, no console errors, search works, cart add/remove works
3. **XSS check:** Create a user/category with `<script>alert(1)</script>` in the name — verify it renders as text, not executable
4. **Git hygiene:** `git ls-files | grep -E 'node_modules|\.env$|output\.css'` returns nothing
5. **Lint:** `cd "cafe-api(Vue)" && npm run lint` passes
6. **Build:** `cd "cafe-api(Vue)" && npm run build` succeeds
