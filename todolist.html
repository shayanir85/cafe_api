با توجه به نیازمندی‌های پروژه، یک To-Do List جامع با تفکیک وظایف فرانت‌اند و بک‌اند تهیه کرده‌ام. این لیست بر اساس اولویت‌های فنی و وابستگی‌های بین بخش‌ها مرتب شده است.

📋 To-Do List پروژه سیستم سفارش‌گیری کافه

🟢 فاز ۱: زیرساخت و احراز هویت (پیش‌نیاز همه بخش‌ها)

اولویت وظیفه فرانت‌اند بک‌اند
۱ پیاده‌سازی سیستم احراز هویت (JWT/Session) صفحه‌های لاگین/ثبت‌نام، ذخیره توکن APIهای ثبت‌نام، ورود، خروج و اعتبارسنجی توکن
۲ تعریف و مدیریت نقش‌ها (کاربر، گارسون، آشپز، ادمین) نمایش/مخفی‌سازی المان‌ها بر اساس نقش میدل‌ور نقش‌ها، مدیریت دسترسی‌های API
۳ صفحه پروفایل و مدیریت اطلاعات کاربر فرم ویرایش پروفایل API بروزرسانی اطلاعات کاربر

🟡 فاز ۲: ماژول سفارش (هسته اصلی پروژه)

اولویت وظیفه فرانت‌اند بک‌اند
۴ طراحی صفحه منو و سبد خرید نمایش دسته‌بندی محصولات، افزودن/حذف به سبد خرید (Ajax) API دریافت منو، API مدیریت سبد خرید (موقت یا دیتابیس)
۵ ثبت سفارش جدید (داخل سالن و بیرون‌بر) فرم انتخاب نوع سفارش، ارسال داده‌ها با Ajax API ثبت سفارش با فیلد order_type (dine-in/takeaway)
۶ گرفتن سفارشات (برای گارسون/آشپز/ادمین) صفحه نمایش لیست سفارشات با آپدیت خودکار (Ajax Polling/WebSocket) API دریافت لیست سفارشات بر اساس نقش (فیلتر شده)
۷ تغییر وضعیت سفارش (آماده‌سازی، تحویل، بسته شدن) دکمه‌های تغییر وضعیت برای هر نقش API بروزرسانی وضعیت سفارش + لاگ تغییرات
۸ ارسال سفارش به آشپزخانه (اتصال گارسون و آشپز) نمایش اعلان برای آشپز هنگام ثبت سفارش جدید ایجاد رویداد (Event) یا WebSocket برای اعلان آنی

🔵 فاز ۳: پرداخت و فاکتور

اولویت وظیفه فرانت‌اند بک‌اند
۹ پیاده‌سازی پرداخت نقدی گزینه انتخاب در فرم پرداخت، تکمیل سفارش بدون درگاه API ثبت پرداخت نقدی و تغییر وضعیت فاکتور
۱۰ اتصال به درگاه پرداخت آنلاین (زرین‌پال/ملی) درخواست Ajax برای دریافت لینک پرداخت، هدایت کاربر، تایید پرداخت API درخواست پرداخت، تایید و تایید نهایی از درگاه
۱۱ تولید فاکتور نهایی و نمایش آن صفحه نمایش فاکتور با امکان چاپ API دریافت اطلاعات فاکتور نهایی

🟣 فاز ۴: اعلان‌ها و پیامک

اولویت وظیفه فرانت‌اند بک‌اند
۱۲ سیستم نوتیفیکیشن داخل برنامه (برای نقش‌ها) نمایش نوتیفیکیشن‌های لحظه‌ای (Toast/Alert) با Ajax یا WebSocket API ثبت و دریافت نوتیفیکیشن‌ها + رویدادهای سیستمی
۱۳ ارسال پیامک به کاربر (تایید سفارش، تغییر وضعیت) در صورت نیاز، درخواست شماره تلفن اتصال به سامانه پیامک (Kavenegar/Farapayamak) و ارسال در رویدادها

⚪ فاز ۵: تنظیمات و مدیریت

اولویت وظیفه فرانت‌اند بک‌اند
۱۴ وضعیت تعطیل بودن کافه (مدیریت توسط ادمین) صفحه مدیریت تنظیمات با سوئیچ تعطیل/باز API بروزرسانی وضعیت تعطیلی، میدل‌ور برای مسدود کردن ثبت سفارش
۱۵ نمایش وضعیت تعطیلی به کاربر نمایش پیام/بنر در صفحه اصلی و منو ارسال وضعیت تعطیلی در پاسخ API منو یا جداگانه

🟠 فاز ۶: بهینه‌سازی و تکمیل

اولویت وظیفه فرانت‌اند بک‌اند
۱۶ پیاده‌سازی بارگذاری مجدد خودکار لیست سفارشات (Ajax Polling یا WebSocket) استفاده از setInterval برای درخواست‌های دوره‌ای یا WebSocket ایجاد وب‌سوکت یا API با قابلیت Long Polling
۱۷ مدیریت خطاها و نمایش پیام‌های مناسب نمایش خطاهای کاربرپسند (مثلاً در صورت تعطیلی کافه) ارسال خطاهای استاندارد HTTP + پیام فارسی
۱۸ واکنش‌گرایی (Responsive) برای موبایل و تبلت طراحی با CSS Framework (Bootstrap/Tailwind) -
۱۹ مستندسازی API (Swagger/Postman) - تهیه مستندات کامل برای فرانت‌اند

📌 نکات کلیدی برای تیم:

برای فرانت‌اند:

  • استفاده از Ajax با jQuery برای همه ارتباطات (به جز WebSocket).
  • مدیریت وضعیت (State) سمت کاربر با ذخیره توکن و اطلاعات نقش در localStorage یا sessionStorage.
  • رعایت امنیت (ارسال توکن در Header تمام درخواست‌ها).

برای بک‌اند:

  • پیاده‌سازی میدل‌ور نقش‌ها برای کنترل دسترسی به APIها.
  • استفاده از WebSocket (مثل Socket.io) یا Redis برای نوتیفیکیشن‌های آنی (اختیاری ولی پیشنهادی).
  • لاگ‌گیری تمام تغییرات وضعیت سفارش برای پیگیری مشکلات.
